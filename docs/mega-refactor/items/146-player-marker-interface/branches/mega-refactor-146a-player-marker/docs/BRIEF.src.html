A player gets a type

A marker IPlayer in the engine gives a player a type and a slot that is never null. Player code takes that type in place of MegaGameEntity, so the compiler tells a player from any other entity.

In play: Nothing changes.

Before and after

The type says "can be a player"; the component says "is a player now"

Code sketch

isDeathOf reads as player-only code

Today, players/PlayerExtensions.kt:

val IGameEntity?.asPlayer: MegaGameEntity?
    get() = (this as? MegaGameEntity)?.takeIf { it.isPlayer }

fun Event.isDeathOf(entity: IGameEntity?): Boolean {
    val player = entity.asPlayer ?: return false
    return getProperty(PlayerEventKeys.SLOT, PlayerSlot::class) == player.playerSlot
}

After:

// engine
interface IPlayer : IGameEntity {
    val slot: PlayerSlot
        get() = playerSlot ?: throw PlayerNotRegisteredException(this)
}

// core
val IGameEntity?.asPlayer: IPlayer?
    get() = (this as? IPlayer)?.takeIf { it.isPlayer }

fun Event.isDeathOf(player: IPlayer): Boolean =
    getProperty(PlayerEventKeys.SLOT, PlayerSlot::class) == player.slot

// call sites
fun contactWithPlayer(player: IPlayer)      // was MegaGameEntity
val target: IPlayer = targetPlayer           // was MegaGameEntity

Decisions

3 decisions

The scan found that almost every read on a player goes through extensions on IGameEntity (body, facing, direction, inPlay). No call site reads a member that only a core type can give. The roster keeps Megaman and X both, and registers only one.

Chosen D1 · No core IMegaPlayer now; the engine IPlayer everywhere.

Chosen D2 · slot throws PlayerNotRegisteredException; asPlayer keeps the component check.

Chosen D3 · targetFor and targetPlayer return IPlayer in this branch.

Chosen D4 · The block filters take IGameEntity; playerAllowsDamageFrom takes IPlayer and the session rules.

Added 2026-11-10 · Tags

A TagsComponent replaces ITaggable and 148 copied overrides

Only core reads a tag, but ITaggable lives in engine. 148 of 155 overrides return the class name; 7 differ (for example SniperJoe_OLD is "SniperJoe", which maps use).

// MegaGameEntity.init()
addComponent(defineTagsComponent())

protected open fun defineTagsComponent() =
    TagsComponent(this::class.simpleName!!)
    // runtime class: FeetRiseSinkBlock
    // gets "FeetRiseSinkBlock"

// one of the 7 that differ
override fun defineTagsComponent() =
    TagsComponent(TAG)  // "SniperJoe"

Today 4 bases (Block, AbstractBlock, Switch, Death) give 34 subclasses the parent's tag.

Chosen D5 · Own name and base name, for example {"FeetRiseSinkBlock", "Block"}.

Chosen D6 · Two components: TagsComponent in core; GroupsComponent stays.

Chosen D7 · No single tag: hasTag and hasAnyTag; each class reads its own TAG; ITaggable and getTag() go.

Added 2026-11-10 · Spawn flow

The engine runs init() before canSpawn; canSpawn reads no per-spawn state

Found at the play test: canSpawn ran before init(), so the GAUNTLET_1 filter crashed on missing tags.

// GameEngine.spawn(), before
if (!entity.canSpawn(props)) ...
// init() ran later, in spawnNow

// after
if (!entity.initialized) initialize(entity)
if (!entity.canSpawn(props)) ...

The contract: canSpawn reads init() data, the spawn props and the session; it never reads per-spawn fields and writes nothing. HeartTank and HealthTank move their parse to onSpawn. Class facts and spawn rules as data go to item 021.

Chosen D10 · From the live player nearest the spawn center, through MegaPlayers.nearestLiveTo, which targetFor also uses.

Risks

A bare type check would count the roster character as a player

  • risk Type is not membership. is IPlayer is true for X in a Megaman level. Every check goes through asPlayer or isPlayer; a core test proves that the character with no slot is not a player.
  • risk Conflicts with 060a and 081f. Both are active and change Megaman.kt, Stuns.kt and PlayerDamageNegotiator.kt. This branch merges master in after each one lands.
  • risk Tags on the web build. The default tag is the class name at runtime. A future minifier (web, Android) can rename classes; a test can only check the JVM build.
  • risk Wide diff. Many files change only a type. The compiler finds each site; the test doubles that act as players must implement IPlayer.
