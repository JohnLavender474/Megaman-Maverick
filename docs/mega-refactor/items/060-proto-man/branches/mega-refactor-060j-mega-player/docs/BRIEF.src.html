A thin abstract class MegaPlayer owns the wiring that Megaman and X both repeat today, and it is the one receiver type of the shared players/ functions. Megaman and X move onto it. Proto Man (060b) is the next class; Bass, Axl and Zero can follow.

Decisions

4 decisions

MegaPlayer holds only what every player class shares (rule O8-R1). Buster, charge, weapons and Megaman's gravity scaling stay out, so Zero, Bass and Axl are not blocked.

D1 · Set the heart-tank max health in the shared spawn, for every class?

Chosen Every class: the shared spawn sets the heart-tank max health.

D2 · Where do the shared values (damage time, start health, sound) come from?

Chosen Read MegamanValues now, with a short TODO at the reads.

D3 · How do the class parts become abstract members?

Chosen Move each part body into the class as the member (Megaman.kt to about 700 lines, MegamanX.kt to about 550).

D4 · Add a test that records the component order of Megaman and X?

Chosen No order test. The review checks the order.

Scope change 2026-11-10

Lifecycle inside MegaPlayer; the run for any entity

A. The lifecycle functions that only MegaPlayer calls become its private members. A move that only some characters use stays a plain function that a class opts in to.

C. Body, jump, wall slide and air dash do not split: no boss or enemy moves like the player (bosses use timed states and aimed jump arcs). They become plain functions that take player: MegaPlayer, not extensions, with a TODO for item 121 (enemy clones). Boss-to-boss copies became item 150.

B. The run splits. The movement part is a plain helper for any entity with a body, so an enemy or boss can move like Megaman. The player part keeps the input and the can-move gate.

Risks

A moved line can change the order of play

  • risk Component order. A few of Megaman's components change place in init(). The scan shows that none of them resets another; the review before the play test checks it.
  • risk Lifecycle lines. 3 lines move inside onSpawn and onDestroy, each independent of its neighbours. Control checks for spawn, death, respawn and the boss gate.
  • risk The base class grows. A later branch can put one character's parts into it. The players/ README gets the rule "only what every player class shares".
