X crouch, ladder and climb

X gets the last moves of his X6 move set: crouch and ladders. Megaman's climb code moves to the shared player code with parameters, so X calls it and nothing is copied.

In play: X crouches on DOWN, grabs ladders from the floor, the top and the air, climbs, shoots on the ladder, and climbs over the top. The art is already in X's atlas. Megaman plays the same.

Before and after

One climb behavior, two callers

Code sketch

Each player passes its climb values

Today, Megaman.defineBehaviorsComponent:

addBehavior(BehaviorType.CLIMBING, climbBehavior())   // Megaman receiver, 230 lines

After:

// Megaman
addBehavior(BehaviorType.CLIMBING, playerClimbBehavior(this, ClimbParams(
    speed = { MegamanValues.CLIMB_VEL },
    canGrab = { !(currentWeapon == NEEDLE_SPIN && shooting) },
    onStart = { aButtonTask = ...; canMakeLandSound = false },
    onEnd = { aButtonTask = ... }
)))

// MegamanX
addBehavior(BehaviorType.CLIMBING, playerClimbBehavior(this, ClimbParams(
    speed = { MegamanXValues.CLIMB_SPEED },          // 5.625 tiles/s (X6)
    onStart = { airDashUsed = false }
)))
addBehavior(BehaviorType.CROUCHING, crouchBehavior())  // megamanx/MegamanXMoves.kt

Decisions

Four decisions

X6 has short animations at the ladder ends; Megaman has none. X's DOWN now drops him through every one-way block, which a ladder grab from the top would replace.

D1 Chosen Share Megaman's climb in players/ with parameters.

D2 Chosen X6 ladder-end animations, with a short lock.

D3 Chosen X6 crouch rules.

D4 Chosen As Megaman: one-way pass only while climbing.

Risks

Megaman's climb is the main risk

  • risk Megaman's climb changes by mistake. A test drives the old and the new climb on the same inputs and compares the positions.
  • risk Conflicts with 060c. The other session changes MegamanX.kt; expect small conflicts in the behaviors list and the animations map.
  • risk Sprite offsets. The crouch and climb frames need their own offsets and buster origins; the play test checks them.
