One shared enemy shot

JunkShot is already a small shared shot: a typed kind holds the region, size, damage, gravity and frames of 4 X6 shots. This branch makes the kind general, gives the class a general name, and moves the first simple Maverick shots into it.

In play: nothing changes. Each moved shot looks, flies and hurts as before.

Before and after

One-off shot classes become kinds

Code sketch

A shooter names its kind

Today, RollingBot:

MegaEntityFactory.fetch(RollingBotShot::class)!!.spawn(props(OWNER pairTo this, POSITION pairTo p, TRAJECTORY pairTo t))

After:

MegaEntityFactory.fetch(EnemyShot::class)!!.spawn(props(
    OWNER pairTo this, POSITION pairTo p, TRAJECTORY pairTo t, TYPE pairTo EnemyShot.Kind.ROLLING_BOT))

// PlayerDamageNegotiator: one entry for every kind
EnemyShot.TAG pairTo dmgNeg { (it as EnemyShot).kind.damage }

Decisions

Three decisions

Damage to a player is keyed by the shot's class or tag today, so a shared class must carry each kind's damage itself.

D1 Chosen Rename JunkShot to EnemyShot.

D2 Chosen One tag entry that reads kind.damage.

D3 Chosen The 4 JunkShot kinds, RollingBotShot and FirePellet.

Risks

A shared class can change who blocks what

  • risk Player shots could start to hit the Rolling Bot shot. JunkShot is damageable, and a player shot stops on a damageable body; the Rolling Bot shot is not damageable today. The kind keeps that off; a test pins it.
  • risk Damage moves path. A test pins each kind's damage (2, 1, 1, 3, 3, 3).
  • risk Pooled reuse. A reused shot resets every kind field at spawn (fixtures, size, draw order); FirePellet keeps flying after a hit, as today.
