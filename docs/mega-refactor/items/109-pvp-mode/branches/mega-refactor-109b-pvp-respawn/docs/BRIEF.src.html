A PvP death respawns only the dead player

In --mode pvp, a death of slot 0 runs the level defeat for both players, and a death of slot 1 has no respawn. After this branch, each dead slot respawns alone at a spawn point. The level defeat never runs in PvP.

In play: slot 1 kills slot 0: no black fade, no music stop, slot 1 stays. Slot 0 beams in at its spawn after 1 s. The same in the other direction. Co-op and single play do not change.

Before and after

The session rule picks the respawn, not the slot number

Code sketch

A typed rule replaces the bool

Today, SessionRules:

val slotRespawn: Boolean = false            // COOP true, PVP false

After:

enum class SlotRespawnRule { OFF, NEAR_PARTNER, AT_SPAWN }

val slotRespawn: SlotRespawnRule = OFF      // COOP NEAR_PARTNER, PVP AT_SPAWN

In SlotRespawn.onDeath, the AT_SPAWN form always starts the slot respawn and returns false, so the screen never starts the level defeat. The spawn props come from the screen: the checkpoint spawn for slot 0, and slotSpawnProps for slot 1.

Decisions

3 decisions

The test room arena has one spawn per slot: slot 0 on the left, slot 1 on the right. Lives are one shared count today.

D1 · Where does a dead slot respawn? Chosen Its own slot spawn point.

D2 · Does a PvP death cost a life? Chosen No life cost, no game over in PvP.

D3 · Spawn protection after the beam-in? Chosen The 1.5 s flash and invincibility, as after a hit.

Risks

Co-op must keep its exact path

  • risk Co-op change. The bool becomes an enum in the co-op path too. Unit tests keep the co-op cases; 2 co-op control checks.
  • risk Death during the level-start beam. Today a slot 0 death then starts the level defeat. The PvP form must not, also there. A unit test covers it.
  • risk Both die in one frame. Each slot must respawn on its own, with no fade. A unit test covers it.
