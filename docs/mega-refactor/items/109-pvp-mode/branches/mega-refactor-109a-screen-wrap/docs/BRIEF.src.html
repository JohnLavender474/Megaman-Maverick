Screen wrap in a wrap room

A room with wrap=true joins its left and right edges, as in the Super Mario Bros. 3 battle mode. Players and shots that leave on one side come in on the other side, and an entity on an edge exists on both sides.

In play: only in the new test map REFACTOR_TEST_109. All other levels play as before.

The game wires one filter into 2 engine systems

After:

val wrap = WorldWrap(
    region = { out -> wrapRoomBounds(out) },          // null unless the room has wrap=true
    wraps = { entity -> WrapPolicy.wraps(entity) },   // players and shots
    maxWraps = { entity -> WrapPolicy.maxWraps(entity) }
)
val worldSystem = WorldSystem(..., wrap = wrap)
SpritesSystem(this::addDrawable, diagnostics, interpolation, wrap)

object WrapPolicy {
    // TODO: per-instance override; enemies, items, effects (item 109, phase 2)
    fun wraps(e: IGameEntity) = e.isPlayer || e is IProjectileEntity
    fun maxWraps(e: IGameEntity) = if (e is IProjectileEntity) 1 else UNLIMITED
}

added 2026-11-19 First, the draw offsets leave WorldSystem. A draw-side BodyInterpolation implements IDrawOffsets and reads only the step number and alpha from the world:

// before: SpritesSystem(this::addDrawable, diagnostics, worldSystem)
val interpolation = BodyInterpolation(world = worldSystem, ppm = ConstVals.PPM)
SpritesSystem(this::addDrawable, diagnostics, interpolation, wrap)

In the step, a body whose center is past an edge moves by ±W with its step start, so interpolation draws no jump. Its contacts stay the same fixture pairs across the edge, so a floor contact does not end and begin again.

Decisions

2 decisions

The camera stays still only when the room is exactly one view wide. Some contact rules read the real fixture shape again, so across an edge they see only the real side.

D1 · Must a wrap room be exactly one view wide? Chosen Yes: the level load throws for any other width.

D2 · Ladders, sand, gravity changers and shot hit points across an edge? Chosen Later: a TODO at each rule.

Risks

The world step is the hot path of every level

  • risk Cost in normal levels. With no region the step does one null check per frame. The allocation test and a step timing test run before and after.
  • risk A floor across the edge is handled twice. On a one-way block the friction adds twice. The test room uses plain blocks; a TODO marks it.
  • risk Queries outside the step. Ground probes and pathfinding do not see across the edge. No enemy uses them in the test room.
