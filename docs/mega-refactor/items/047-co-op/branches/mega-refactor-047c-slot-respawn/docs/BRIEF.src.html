A dead player respawns near the partner

In co-op, a dead player of either slot comes back next to the live partner after 1 s, at a safe spot, with the beam. Each death costs one life. The level resets only when no player is alive.

In play: today a dead slot 1 stays out until slot 0 dies, and slot 0's death resets the level. After this branch either player beams down beside the partner, on the side the partner faces, never in a wall, over a pit or on spikes.

Before and after

A death while the partner lives gets a short respawn; the reset needs every player dead

Code sketch

The level screen starts a slot respawn while a partner lives

Today, MegaLevelScreen.onEvent:

EventType.PLAYER_JUST_DIED -> {
    val slot = event.getProperty(PlayerEventKeys.SLOT, PlayerSlot::class)!!
    if (slot.index != 0) return
    respawn.startAtDeath()
}

After:

EventType.PLAYER_JUST_DIED -> {
    val slot = event.getProperty(PlayerEventKeys.SLOT, PlayerSlot::class)!!
    when {
        respawn.running -> return                               // the reset's own destroys
        !game.players.anyOtherLive(slot) -> { slotRespawn.cancelAll(); respawn.startAtDeath() }
        game.rules.slotRespawn -> slotRespawn.start(slot)       // one life, then 1 s
    }
}

// SlotRespawn.update(delta), per waiting slot
timer.update(delta)
if (!timer.isFinished()) return
if (!partnerSpot.find(player, partner, spot)) return  // waits: partner in the air, no safe spot
engine.spawn(player, spawnProps(spot, gravity.direction, partner.facing))
beam.start(player)                                    // PRE_PLAY until the beam lands, then IN_PLAY

Decisions

Your 4 answers are in

Chosen D1 · One life from the shared count per death. At 0 lives, the dead player stays out until the next level reset; a death that leaves a live partner never causes a game over.

Chosen D2 · After 1 s, beam down at the spot (no fade, no "READY" text).

Chosen D3 · Slot 0 also respawns near slot 1 while slot 1 lives; the level reset comes only when no player is alive.

Chosen D4 · The gauntlet waves go on; the player respawns into the fight.

changed 2026-11-09, from D3 The level screen rules that read only slot 0 now read "any player": the camera hold, the room scan, the view edges, the room exits, the pause gate and the death fade. A boss fight and the level end act on the first live player. The pause button stays slot 0's (047d).

Risks

The larger risk is the slot 0 rules with slot 0 dead

  • risk The reset sends a slot 1 death too. Slot 0's death destroys slot 1, and that sends the same event. The respawn ignores it while the routine runs; a test checks it.
  • risk Gravity. A player spawn sets the gravity of the session from its props. The respawn passes the current direction, so slot 0 never turns; a test checks it.
  • risk Slot 0 dead, slot 1 plays. About 10 level screen rules and the room scan read slot 0 today. Each gets a test with slot 0 dead; the play checks walk slot 1 through a room edge alone.

Also in this branch: the two filed bugs (weapon sets survive a death; the axe throw has no live check), and a precious guard that breaks on the other player's death.
