Pool ownership

A pooled object is now only a scratch for the current frames and is never stored. Data that lives longer is copied into fields that the entity owns. There is no free() any more, and a dev flag makes each stored scratch show at once.

In play: nothing changes, except fixes of entities that kept a pooled object and could see it change under them (for example a lift stop point, a crusher start, an Electrocutie post).

Before and after

One owner for each object, no manual free

Code sketch

An entity owns what it keeps

Today, DrillHead:

private val hoverSpots = Array<Vector2>()
// onSpawn
hoverSpots.add(rect.getCenter(false))
// onDestroy
hoverSpots.forEach { GameObjectPools.free(it) }

After:

private val hoverSpots = OwnedArray { Vector2() }
// onSpawn
rect.getCenter(hoverSpots.add())
// onDestroy
hoverSpots.clear()

Decisions

Four choices, taken with the recommendation

The owner asked for the branch end to end with no stops. Each choice below is Claude's, and the owner can change it at the play test.

Scratch-only pool; owned fields and OwnedArray; no free(). No double free, no leak. Keep free() and add an assert. Keeps the scattered free() calls. Not now: no caller needs an exact lifetime. Backlog candidate. Add it now. An API with no real caller. --poolChecks: poison at reclaim and never reuse, so a stored scratch stays NaN. Poison plus a generation map. More code, it only reports what the poison shows. Keep 3. Each legal lifetime crosses at most 1 or 2 frame edges; each unsafe one lasts seconds, so 4 or 5 only hides it. Raise to 4 or 5. A larger pool peak, no real safety.

Risks

Many entity files change at spawn time

  • risk A shared reference was on purpose. A copy breaks a live link. Each changed site was read; the play checks cover the live entities.
  • risk --poolChecks finds old faults. That is its job; a fault in a check is a bug to fix, not a failure of the flag.
  • risk No frame-time capture. The game is not launched on the branch; a --diagnostics run can come with the play test.
