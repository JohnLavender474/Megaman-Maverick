Spawn allocations

A pooled entity now makes its timers, cullables, motions, sprites and vectors once and sets them on each spawn. The shared spawn paths of all enemies, shots, items and blocks come first, then the often-spawned classes and the per-frame leftovers of 045a. A guard test keeps the count from growing.

In play: nothing changes. A few fixes have no visible effect: leaked cull listeners, debug shapes that grew on each spawn, and a reused cull timer that did not start at zero.

Code sketch

AbstractEnemy keeps its cullables

Today, in AbstractEnemy.onSpawn:

val eventsToCullOn = objectSetOf<Any>(GAME_OVER, LEVEL_RESET, ...)
val cullOnEvents = CullableOnEvent({ eventsToCullOn.contains(it.key) }, eventsToCullOn)
services.events.addListener(cullOnEvents)
runnablesOnDestroy.put(CULL_EVENTS) { services.events.removeListener(cullOnEvents) }

After:

private val cullOnEvents = CullableOnEvent({ cullEventKeys.contains(it.key) }, cullEventKeys)
private val removeCullOnEvents: () -> Unit = { services.events.removeListener(cullOnEvents) }
// onSpawn
cullOnEvents.reset()
services.events.addListener(cullOnEvents)
runnablesOnDestroy.put(CULL_EVENTS, removeCullOnEvents)

Decisions

Risks

A reused object keeps old state

  • risk Old state. Each reused object is reset to its constructor state; spawn-twice tests cover the shared paths and Saw; the play checks spawn each entity twice.
  • risk A child keeps a scratch. Each child that now gets a scratch was read; --poolChecks shows a miss at once.
  • risk No frame-time capture. No game launch on the branch.
